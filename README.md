完整 Next.js + Node.js 项目，包含文案仿写、图片提字、原图换字、本地小红书模板、字体、图片素材、PNG/长图/分文件夹 ZIP。

**交接状态：2026-11-06。部署现有网站，不要重新生成或改写网站。**

## 部署

需要 Node.js 24、pnpm 9。项目代码和素材均在仓库，无需 Codex 聊天环境。

1. 导入完整仓库/源码 ZIP，进入含 package.json 的项目根目录。
2. 在扣子服务端环境变量/密钥配置中按 [.env.relay.example](./.env.relay.example) 填写。当前方案两项 provider 都是 relay；CONFLUX_API_KEY 使用已有中转站密钥。真实密钥不在公开仓库中。
3. 执行：

```bash
pnpm install --frozen-lockfile
node scripts/check-deployment.mjs source
pnpm build
pnpm start
```

.coze 已指向项目生产脚本。Linux 执行 bash 脚本，Windows 有对应 ps1。服务器端口由 DEPLOY_RUN_PORT 控制，缺省 5000。不能只发布前端静态页面，/api/* 需要 Node.js。

构建检查会拒绝缺失/不一致的 provider 配置、生产调试落盘，以及源码/字体/素材的非预期变化。启动还检查当前通道与构建时是否一致、relay 密钥是否填写。错误出现时按说明修正配置或恢复文件，不要改模型或删除校验。

## 已保留的使用流程

一套素材 → 选择 1–100 条独立文案 → 检查修改 → 每条搭配不同模板 → 本地排版 → 各套分文件夹下载。

封面为半张大标题加半张完整大图。后续页面的普通首句不冒充标题；真实小标题仅比正文稍大。标题可修改；上传的图表不重绘、不拉伸；纯文字截图不嵌套为小图片。

## 验收与完整性

发布基线位于 release-integrity.json，统一以 LF 计算文本 SHA-256，二进制按原始字节校验，因此兼容 Windows/Linux。普通部署只校验，不自动重建基线。用户明确授权功能变化并验证完成后，发布人员才能执行 node scripts/create-release-manifest.mjs --approved-release 更新基线。

本机测试结果见 [DEPLOYMENT_VERIFICATION.json](./DEPLOYMENT_VERIFICATION.json)。目标扣子服务器仍需完成环境变量、认证、域名和模型调用验收；没有实际部署验证的项目不应标为已通过。
